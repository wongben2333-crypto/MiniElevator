# 01 · 游戏设计文档（GDD）

> 上层入口见 [README](../README.md)。本文描述"游戏是什么、玩什么、怎么输赢"。

---

## 1. 一句话定位

**你是摩天楼的垂直交通总调度，用"画线路"的方式设计一套电梯系统，看它在早晚高峰里活起来——地铁的皮，电梯的骨，调度的魂。**

## 2. 设计支柱（Design Pillars）

1. **观察型系统**：玩家布置好系统后，电梯自动运转，玩家观察、诊断、迭代，而非实时微操。
2. **拓扑即策略**：核心决策是"哪部电梯停哪些层"（换乘网络）与"用什么调度策略"。
3. **时间塑造需求**：与 Mini Metro 的空间随机不同，本作的难度来自**时间**——早晚高峰、午间潮汐、突发事件。
4. **极简可读**：一屏看懂整栋楼的状态；颜色/形状承载信息，尽量不用文字。
5. **失败可归因**：输掉时应能指出"是哪层/哪条线路成了瓶颈"，而非莫名其妙。

## 3. 与 Mini Metro 的对应关系

| Mini Metro | 本作 | 说明 |
|---|---|---|
| 车站 | 楼层 | 1F 大堂是天然枢纽；另有特色层（空中大堂/餐厅/医院急诊/停车场） |
| 地铁线（颜色） | **电梯/电梯组（颜色）** | 一条"线"= 一部（或一组）电梯的**有序停靠楼层表** |
| 列车 | 电梯轿厢 | 在大楼剖面里上下运行 |
| 隧道 | 井道 | 资源，决定能放几部电梯 |
| 车厢扩容 | 容量 / 双层轿厢 | 升级项 |
| 乘客形状 | 乘客颜色 / 图标 | 颜色=目的区，图标=需求类型（办公/病人/VIP） |
| 换乘站 | 多部电梯共同停靠的楼层 | **换乘 = 电梯之间转乘，本作核心乐趣来源** |
| 新站出现 | 楼层加建 + 租户入驻 | 需求随时间/天数增长 |
| 车站挤爆 → 游戏结束 | 楼层"拥挤压力条"满 → 停运/投诉 → 结束 | 失败条件 |

## 4. 差异化设计（让它不只是"1D 版地铁"）

Mini Metro 的魔力来自 2D 拓扑（线可交叉、成环、分支）。电梯只有上下 1 维，若照搬会单调。用三点补足：

1. **换乘网络 = 隐式的 2D 拓扑**
   向真实超高层的"空中大堂"致敬。低区电梯 + 高区电梯 + 高速直达梯在大堂层交叉；玩家设计的是**区域 × 楼层的分层结构**，换乘点即"交叉站"。

2. **时间方向性 = 调度魂**
   地铁基本不分方向，电梯分。早高峰 = 大堂往上灌；晚高峰 = 全楼往下泄。玩家要解决**空驶返程（deadhead）**——如"满载直达顶层，空车快返大堂再接一批"。这是纯策略增量。

3. **调度策略层 = 招牌机制**
   玩家不只画线，还能给每部电梯设策略：上行高峰直达 / 下行扫楼 / 纯本区 / 全叫。这是区别于地铁、也呼应"电梯调度"主题的关键。

## 5. 核心循环

```
看楼 → 画/改线路(拓扑) → 设调度策略 → 放它自动跑
   → 观察拥堵/换乘/空驶 → 拿升级 → 楼长高 / 需求变大 → 再调
```

一"天"约 3–5 分钟实时，含 **早高峰 → 午间 → 晚高峰 → 夜间**；存活一天后进入升级期。

## 6. 系统拆解

### 6.1 楼层（Floor）
- 编号 `B2, B1, 1F … N F`；`1F` 为大堂（默认枢纽）。
- 特色层带需求模式：
  | 特色层 | 需求模式 |
  |---|---|
  | 大堂 | 全通过，早晚高峰核心 |
  | 空中大堂 | 换乘枢纽，中区汇聚 |
  | 餐厅 | 午间上冲 |
  | 停车场 | 早晚潮汐 |
  | 屋顶酒吧 | 夜间上冲 |
  | 医院急诊 | 优先级乘客 |
- 每层带 **压力条**（拥挤度），是失败判定的载体。

### 6.2 乘客（Passenger）
- 属性：`起点 → 终点`、方向（上/下）、耐心计时、小团体 1–4 人。
- 状态：`WAIT`（等梯）→ `RIDE`（乘梯）→ `TRANSFER`（换乘等待）→ `DONE`。
- 特殊体：VIP / 担架 / 轮椅（需无障碍轿厢，超时惩罚）。
- 行为：按**寻路计划**前进（见 [03 · 寻路](03-pathfinding.md)）；耐心耗尽 → 计入该层压力。

### 6.3 电梯轿厢（Elevator）
- 属性：容量、速度、**停靠序列表**（有序楼层表，可跳层=直达）、方向、状态、载客数。
- 运动：沿停靠表往复运行（到底反向），非环线。可在相邻停靠层间直达，跳过中间层。
- 调度：由所选**策略**决定"在停靠表上哪些站真停、是否接客、是否空驶返程"（见 [04 · 调度](04-dispatch.md)）。

### 6.4 线路编辑（核心操作）
- 在大楼剖面里从楼层拖到楼层，生成该电梯的**有序停靠序列**。
- 两部电梯在共同楼层"相交"即可换乘。
- 实时预览；松手校验（去重、相邻关系）。

### 6.5 调度策略（每梯可设）
- `纯本区`：只服务自身楼层集合。
- `上行直达`（UpPeak）：大堂满载 → 直达最高需求层 → 本地返回。
- `下行扫楼`：下行逐层停。
- `全叫`：不拒反向客（低效但公平）。
- `空驶优化`：返程不停，快速回大堂接客。

### 6.6 资源与升级（类比 Mini Metro 每周奖励，二选一）
🚪 新井道+轿厢 ｜ 📈 容量 ｜ 🚀 速度 ｜ 🛗 双层轿厢 ｜ ⏭️ 直达跳层权 ｜ 🌉 空中连廊（跨楼换乘） ｜ 🛠️ 维修（解除故障）

### 6.7 失败条件
某层等待人数超阈值 → 该层压力条上涨 → 持续满格 → **停运 / 投诉 / 疏散 → 结束**。
辅助指标：全局"平均等待 / 满意度"。

### 6.8 评分
送达人数、平均等待、总行程、能耗（越低越好）、换乘次数、星级。

## 7. 难度曲线与事件

- **加建**：大楼逐层变高、租户逐日变多。
- **时段潮汐**：早高峰上行、午间双向、晚高峰下行、夜间局部。
- **突发事件**：停电（降速/停部分井道）、检修（某梯停运一天）、消防演练（全员下到地面）、VIP 到访（超时罚分）、新租户入驻（某层人数暴涨）。
- **故障**：轿厢随机下线，考验冗余设计。

## 8. 建筑 / 关卡类型（类比城市地图）

| 地图 | 特点 | 难度 |
|---|---|---|
| 办公楼 | 强早晚高峰，标准教学 | ★ |
| 医院 | 优先级/担架，楼层垂直分布 | ★★ |
| 商场 | 多站短程、双向客流 | ★★ |
| 酒店 | 大堂+客房+餐厅+宴会，事件多 | ★★★ |
| 综合超高层 | 空中大堂 + 直达梯 + 多分区，终局图 | ★★★★ |
| 太空电梯 / 未来塔 | 趣味变体（如低重力加速） | 彩蛋 |

## 9. 美术与氛围

- **剖面侧视**，极简扁平矢量；楼层为细横线，大楼轮廓向上生长，窗外城市视差。
- 乘客 = 小色块（颜色=目的区，形状=需求）；轿厢 = 彩色胶囊。
- 灯光随时段暖 → 冷；人群嘈杂声随等待上升；到站轻"叮"；拥挤拉警报。
- 参考气质：Mini Metro × Monument Valley × 电梯环境音。

## 10. 操作

- 拖拽 = 设停靠序列
- 点轿厢 = 切策略
- 空格 = 暂停进入"规划模式"
- 触屏 + 鼠标 + 键盘提示

## 11. 设计风险与对策

| 风险 | 对策 |
|---|---|
| 只有上下、视觉/玩法单调 | 分区 + 空中大堂换乘、跨楼连廊、时段方向性 |
| 变成疯狂点按微操 | 自动调度策略；玩家只管"拓扑 + 策略" |
| 换乘/等待不可读 | 强颜色编码 + 楼层压力条 + 换乘动画 |
| 数值难平衡 | 数据驱动 + 无头跑分 + 确定性回放 |

## 12. 非目标（明确不做）

- 不做 3D、不做物理破坏、不做剧情叙事。
- 不做多人联机、不做后端排行榜（个人实验）。
- 不做开放世界城市；始终聚焦"一栋楼"。
